# dm-puzzles-microsite-nuxt

Nuxt 4 SPA (`ssr: false`) microsite for Sticky Puzzles (Digital Marmalade). Vue 3 `<script setup>`, Pinia, `@nuxtjs/i18n`. Puzzles themselves are separate apps embedded via an iframe channel: `pages/puzzle/[id].vue` sets `window.channel` before the frame loads (the puzzles only switch their channel on when it exists) and opens a `PuzzleChannel` (`app/lib/puzzleChannel.js`, a module copy of the dm-mpuzzles global build until `@digitalmarmalade/dm-puzzle-channel` can be installed from GitHub Packages) with `bubble: true` so other frames' messages still reach their listeners; each `{content, status}` event is unpacked into the legacy `{status, …stats}` payload and handled alongside the older `{type, payload}` postMessages; this repo is the surrounding site — home, archive, account, friends/stats, streaks, onboarding.

## Working conventions

- **Comments: default to ZERO.** Do not add comments that narrate what the code does, restate identifier names, or explain why a change was made. Only a rare comment that stops a future reader silently reintroducing a bug earns its place — a single short line, never a header above each function/computed/rule. This applies to JS, Vue, CSS, and HTML. Jeremy has asked for this many times; treat justification/rationale/reason-for-change comments as banned.
- **i18n: every user-facing string goes through `$t()`, and all 7 locale files stay in sync.** Locales: `i18n/locales/{en,fr,it,de,es,hu,pl}.json` (en is default; `strategy: 'prefix_except_default'`). Add a key to all 7. Non-English strings are machine-translated and need a native/professional review before launch — flag new ones rather than assuming they're final. Use `<NuxtLinkLocale>`, `useLocalePath()` (bind in `<script setup>`, not template), and `useDateLocale()` for dates (NOT `useI18n().locale`).
- **CSS: one rule per selector holds everything** — base declarations, its `@media`/breakpoint/`@container` overrides, and its `:hover`/`:focus` states — nested via `&`. Never a separate `@media {…}` section or a second rule for the same selector just to hold a media query. `app/styles/css/card.css` is the reference. Native nesting is supported by the Vite pipeline.
- **Page reveals:** `app/plugins/reveal.client.js`. On page load everything on screen is simply shown, except the archive grid (`.archive-main .puzzle-card-grid`), whose cards fade in (no slide, 0.01s apart, `data-reveal-fade`). Archive cards below the fold fade in as they scroll into view; everything else on every page simply appears. Candidates are found from the direct children of `main .wrapper` (a block containing a card grid is split into its items); nothing animates for reduced motion or a page opened in a background tab. Blocks are marked with `data-reveal` (not classes, which Vue rewrites), the page wrapper is hidden from `page:start` until they're marked, and the hidden state forces `transition: none` so components' own transitions can't animate it. The home page's first visit is recorded in sessionStorage `sp-intro-seen`, which `StreakPanel` uses to animate only then. Styles in `app/styles/css/animations.css`.
- **Cache-busted assets:** reference the sprite through `sprite(id)` / `spriteFile()` and achievement images through `achievementImage(id)` (`public/img/achievements/{id}.webp`; `app/utils/assets.js`, auto-imported; `versioned(path)` for anything else), which add `?v={buildVersion}` so a deploy busts cached copies.
- **Tile shadows scale with the tile:** `.puzzle-icon-holder` is an inline-size container and the puzzle icon's `--tile-shadow` is written in `cqi` (set at the default 8rem icon), so a tile keeps the same proportions at any `--card-icon-size`; don't override `--tile-shadow` per size. Achievement medal stamps do the same with a `.stamp-holder` container (`--stamp-size`), including their corner radius and lettering; their styles are shared in `app/styles/css/medal.css` (used by the achievements and the Wrapped medal slide).
- **Theme:** `sp-theme` localStorage ('light'/'dark' override only) drives a `data-theme-status` attribute on `<html>`; no attribute = follow OS via `prefers-color-scheme`. See `app/composables/theme.js` and `variables.css`.

## Current focus — onboarding & stats roadmap

Full plan (with diagrams) lives in a Claude Docs doc: <https://claude.ai/code/artifact/2536765b-a3f9-4b27-a77f-326d338f27c3>

Thesis: the personalisation/stats engine is already built (persona engine, tiered achievements, per-type charts, favourites that re-rank home) but passive, device-local, and was gated behind a modal — the work is to *activate and persist* it.

**Phase 1 shipped** (first-visit = play):
- Onboarding no longer auto-opens; it's an opt-in tour reached from the dismissable `HomeWelcome.vue` strip and the account page. The strip only shows to genuinely new players (fewer than 3 completions, on fewer than 2 days, and no older solves in the lifetime rollup), so it never sits alongside the monthly Wrapped banner, which needs last month's play. It works like the puzzles' own guide (dm-mpuzzles `guide.js` / `body-guide.blade.php`): `OnboardingModal.vue` is a full-screen swipeable slideshow (dots at the top, buttons at the bottom; the first slide keeps the `OnboardingIconRain` drop-in, the second is "Pick your puzzles": every branch as a card in alphabetical order, tapping it toggles it as a favourite, the eye in its corner hides it (hiding drops a favourite, favouriting unhides), the same type filter pills as All Puzzles sit above the cards, and Try it opens that type's tutorials (`TutorialPractice`) in a window over the slideshow; the streak slide animates and the profile slide shows a sample player-profile card) (daily, pick your puzzles, streak, profile, plus the free daily puzzle for logged-out visitors on login sites) ending in Close or Show me around; that starts the feature tour, `GuideTour.vue` + `useGuide()` in `app/composables/guide.js`, which points at real home elements (`data-guide` attributes: your-puzzles, today, summary, profile, all, nav-stats, free) with a tip whose arrow points at the target, placed below/above/beside or docked; only nav items also get the orange outline, and on mobile a "The menu" step first points at the burger (`data-guide="nav-menu"`), then the Stats step opens the menu (shared `nav:menuOpen` state) and closes it when the tour moves on; the bubble fades out while the page scrolls and back in once it settles, "n of total", End tour / Next, arrows and Esc, skipping anything not on screen, and ends on "Ready to play?" with Play for today's top pick (taste model). `showTip(id, text)` gives once-only context tips (saved in the synced preference `guideTips`): the Your Puzzles row for players who skipped the tour, and the challenges turn-off tip. Funnel: `sp_tour_open/complete/skip` for the slides, `sp_feature_tour_start/complete` for the tour.
- **Anonymous visitors get 1 free puzzle a day:** all of today's puzzles are unlocked until they open one (any of them); after that the rest lock and the one they picked stays open to finish. Enforced in `app/middleware/auth.global.js` via the reactive `app/stores/freePlay.js` (localStorage `sp-free-play`). `PuzzleCard.vue` hides the padlock while a free play is available; `LoginGateBanner.vue` reflects the free/used state. When a logged-out visitor opens a gated page, `LockedNotice.vue` shows a teaser of what's behind it instead of a padlock: Stats gets `StatsTeaser` (hero + achievement cards), Friends gets `FriendsWelcome` with `sign-in` (Log in / Sign up instead of Create / Join), Account gets `AccountTeaser.vue`; all built from the shared `FeatureHero` and `FeatureCard` (`app/components/generic/`). Accounts are free on every brand, so user-facing copy never says "free puzzle" or "subscribe": the first puzzle "needs no account", and the call to action is "create a free account" / "Sign up" (`auth.signUp`).

- **Funnel metrics** (`app/composables/funnel.js`, device-local state in localStorage `sp-funnel`) go to Firebase Analytics/GA4 as `sp_*` events: first visit/play, tour open/complete/skip, free-play claim/wall/convert, return + D1/D7. Visitors who predate tracking are flagged `legacy` and excluded from first-visit/retention.

**Phase 2 built** (learn from play): `app/lib/tasteModel.js` scores every puzzle branch from favourites, tour picks and the completion log (behaviour overtakes explicit choices as history grows); it orders the home **Your Puzzles** row (`YourPuzzles.vue`, picks and reasons in `app/lib/yourPuzzles.js`), which only lists today's puzzles the player has a clear reason to like — favourite, a category they asked for, a step up, their usual puzzle for this time of day, played 2+ times in 30 days, a streak to continue (played yesterday, not yet today — this reason wins over the others), or a tour pick while history is thin — each with a one-line reason. Completed puzzles leave the row; while fewer than 5 of today's picks are left, it tops up to 5 with archive puzzles of the types finished today ("Missed this one?"), at most one per type: an unfinished one already started, otherwise the newest unsolved, and once all are done an "All done for today" card linking to the archive leads the row. Today's grid stays in archive order. The home page runs Your Puzzles, the banners row, the summary row (streak, last 7 days, challenges), then Today's Puzzles; when Your Puzzles has nothing to show, the summary row moves below Today's Puzzles so the page never opens on stats (the row's cards come from `useYourPuzzles` in `app/composables/yourPuzzles.js`, called by the page so it knows before rendering). The All Puzzles pills (`usePuzzleFilters` in `app/composables/puzzleFilters.js`, shared with the onboarding pick slide) are All, Words, Numbers, Logic (from `PUZZLE_META` types) plus Quick, any type with `time` ≤ `QUICK_MINUTES` (4, in `app/composables/puzzle.js`, also used for the "Another snack-sized puzzle" suggestion). There is no category nudge (the "You keep coming back to … puzzles — want them first?" prompt was removed); instead Your Puzzles suggests a type the player hasn't played in the last 30 days when they've played others in its category at least twice, with the reason "Because you like {category} games" (`likeCategory` in `app/lib/yourPuzzles.js`, text under `home.yourPuzzles.reasons.likeCategory.{words,numbers,logic,quiz}`); categories boosted by earlier answers still count ("You asked for more of these"). `HomeNudge.vue` and the post-completion toast now only carry the level cue.

**Phase 3 built** (the site decides difficulty, the puzzles apply it): the site keeps per-puzzle assist levels (`app/stores/assists.js`, rules in `app/lib/assists.js`), passes them in as `window.puzzleApp.assists` (the page also passes `window.puzzleApp.related` = `{heading, icon, title, theme, url}` for the completion screen's next-puzzle card, read once when the puzzle loads; just before the iframe starts, `useNextPuzzle` in `app/composables/nextPuzzle.js` picks the first that applies, skipping this puzzle, solved, hidden and unreleased ones: a type on a streak (played yesterday, not today), an unfinished puzzle, the next Your Puzzles pick with its reason, another snack-sized puzzle (≤ 4 min) after a snack, then the newest unsolved archive puzzle of this type (or the next older one when already in the archive); the url carries `?next={reason}`, tracked as `sp_next_click` and stripped on arrival; logged-out visitors on login sites and anything else fall back to the completion data's second link); at the same moment the completion screen's Play another link (`completion.{correct,incorrect}.links[0]`) is replaced by `anotherFor` in the same composable: the next unfinished, released puzzle of the same variant, older first then wrapping round to newer ones, with `?next=another`; when every one is finished it points to that variant's archive page, and receives the player's completion-screen rating as a `puzzledifficulty` message. Ratings lean the taste model, and a one-time "ready to try {level}?" cue uses the nudge UI (switched off by the `levelNudge` feature flag, off by default; it gates both the home banner and the completion toast in `useTasteNudge`; the `nudge-level` / `level-toast` previews still show them for styling). Puzzles keep the mechanics and their own defaults when run standalone. Two types have assists. Crossword's help is **letter picks** (`kind: 'letters'` in `RULES`; level 0–6 → `letterPicks()` consonants then vowels): when the planned level is above 0, pressing Play on the cover opens `PuzzleLetterPicker.vue`, a step before the iframe where the player picks that many letters (consonants first; the vowels group only appears at the higher levels; tiles never lock: tapping another letter in a full group swaps out its oldest pick, and a full group's count turns `--primary` with a tick; last picks remembered per tag in `sp-assist-letters`, never suggested), and the puzzle gets `puzzleApp.assists = {type: 'letters', letterLevel, letters}` (it fills in every instance). Starter cells count as reveals in both puzzles, so a helped solve is never a clean solve; the puzzles also send `prefilled` (how many cells were filled before play), stored on the completion, and the 3-clean-solves offer of less help subtracts it so starter cells alone don't block it. The cover's secondary button only appears when Play includes help, and it always plays without it ("Play without picking letters"); with no help planned there's just Play. Old Crossword starter-letter levels (`prefillPercent` under the `crossword` tag) are converted to letter-pick levels on load and on read (`fromStarterLetters` in `stores/assists.js`). Sudoku's help is **starter squares** (`kind: 'percent'`, `prefillPercent` 0–40 in steps of 5, starting at 10): the puzzle fills in that share of the open squares before play. With help planned, Sudoku's cover says "You told us you found {name} hard last time…" (`cover.assist.sudoku.adjusted`, `{name}` = the variant). Three clean solves still offer fewer. The rule is by type, so it covers Huedoku and Sudoku Hard too, but levels are saved per tag, so each keeps its own. For any type with a rule the page always sends a level (`{prefillPercent: 0}` when nothing is saved), so a level saved inside the game can't override the site. `?preview=letter-picker` forces the step at level 4 on any Crossword. Funnel `sp_letters_pick` / `sp_letters_skip`. Every puzzle opens on `PuzzleCover.vue` (icon, name, number, date, a "Last time" panel of stat tiles styled like the archive stats, and Play); the iframe only loads after it. Puzzles already started or completed skip it, and so do multiplayer invite links (`?gid=`). When a game is started or left inside the frame, the frame's `gid` is copied onto the page's own URL (`syncGameId`, on frame load, when the page is hidden and on `pagehide`), so an iOS home-screen app reloaded after being in the background reopens the same game. The Last time tiles use each type's `gameConfig().chart` measures (time, guesses, reveals, checks, hints, mistakes, words found; hints are Sudoku/Huedoku/Sudoku Hard/Takuzu's "Show me a step" count, `hintsShown`, also drawn as its own line in the archive chart; any hint stops a clean solve, in `isCleanSolve`, `isGlobalCleanSolve` and the 3-clean-solves offer of less help) and the panel is hidden when the last solve recorded none. On a fresh puzzle with assists the puzzle page builds a plan (`buildPlan` in `pages/puzzle/[id].vue`): a message when the level was adjusted ("Based on your feedback…") plus two buttons — Play (the planned level) and a secondary Play without / with / with more starter letters, which only affects that game. Help is opt-in: the site never adds help on its own, so extra help only follows a Hard rating and the player's choice in `ModalAssistFeedback.vue`. The only offer from past play is 3 clean solves → less help (`suggestAssists` in `app/lib/assists.js`); the primary button accepts it and the secondary declines; each offer is based on the latest solve and asked once, with a 3-day pause after a no (`sp-assist-offers`). An Easy/Hard rating from the puzzle opens `ModalAssistFeedback.vue`, worded for the puzzle's kind of help (letters: "How many help letters shall we let you pick next time?" plus how many were picked this game, and More / Fewer show the resulting count; other kinds a generic title; the choices are one row of joined pill segments like the puzzles' completion-screen rating, filling `--primary` when picked): after Hard it offers The same / More / A lot more, after Easy None / Fewer / The same (`assistOptions` drops any that would land on the same count), and `adjustAssists` in `app/lib/assists.js` turns the choice into the new level (More = one step, or the start level from off; A lot more = three steps; Fewer = half, rounded down to a step; None = off); a `puzzledifficulty` that still carries `assists` (older Crossword builds) is applied directly without the modal.

**Transparency:** the account page's `LearnedAboutYou.vue` lists what the site has inferred (`buildInsights` in `app/lib/insights.js`): puzzles played 2+ times in 30 days, usual time of day per puzzle, difficulty leans, saved assist levels, category boosts and tour picks. Removing one really switches it off: `likes:`/`time:`/`lean:` ids go into the synced preference `dismissedInsights`, which `buildTasteModel`, `levelCue` and `pickYourPuzzles` honour; assist levels are cleared, boosts move to declined, tour picks are emptied. "Remove all" (which replaced the old "Reset puzzle suggestions" button) does all of that at once and also clears nudge answers; "Bring back" clears `dismissedInsights`.

**Phase 4 built** (tailoring follows the account): `app/plugins/profileSync.client.js` keeps one Firestore doc, `users/{uid}/settings/microsite`, in step with local storage (favourites, hidden, synced preferences, assists, completion log, streak-freeze days, unlocked achievements, lifetime rollup). Completions live in month docs `users/{uid}/history/{YYYY-MM}`, and any device that has ever synced (`sp-sync.uid`) keeps its full log (`challenges.keepFullLog`). Only never-synced devices trim the log to 90 days, folding older solves into monthly totals (`app/lib/lifetime.js`). Merge rules live in `app/lib/profileSync.js`. Each device listens to its profile doc (`onSnapshot`) and pulls 1.5s after another device saves, so changes arrive live; a push writes the history months first and the profile doc last, so the profile's `updatedAt` marks a finished save. It also pulls on sign-in, on page load and on returning to the tab after a minute. Per-puzzle completion state isn't synced separately: `playStatus` (IndexedDB, this device only) fills in every slug in the synced completion log as completed (`withCompletions` in `app/stores/playStatus.js`, re-applied whenever `challenges.completions` changes), so cards, family levels and the cover show puzzles solved on another device. In-progress state and the puzzle's own saved grid stay on the device.

**Practice puzzles:** a type with `tutorial: n` in `PUZZLE_META` (`app/lib/config.ts`) swaps its microgame for `TutorialPlayer.vue`, which frames a copy of the gameplay kept in `public/tutorials/{slug}/` one puzzle at a time (`/tutorials/{slug}/index.html?json=/tutorials/{slug}/{slug}-{n}.json&tutorial=1`, built by `useTutorial`) and only trusts `tutorialready` / `tutorialstart` / `tutorialcomplete` messages from its own frame, either as channel events (it opens a `PuzzleChannel` per step's frame and claims `window.channel` via `claimWindowChannel()` in `app/composables/windowChannel.js`, shared with the puzzle page, so channel-era tutorial builds switch their channel on) or as older `{type, payload}` postMessages (`tutorialcomplete` carries `solved: false` when a GuessWord is lost or a Word Wheel is ended early, which still ends the step) (funnel events `sp_tutorial_start` / `sp_tutorial_complete`). Each practice puzzle is its own button (`TutorialLessons.vue`), ticked once done, and plays alone (`single` + `start` props). On the cover a Tutorials panel lists them with Start/Replay and swaps the card for the player, with a close button back. In the info modal, the announcement's Learn how to play modal and the tour's Try it window (`TutorialPractice.vue`) the first one plays straight away and the buttons act as tabs above it; finishing one offers the next, the last offers Replay. Completed steps are saved in the synced preference `tutorialsDone` ({slug: [steps]}), and finishing them all unlocks the per-type "{name} Trained" achievement (`tutorialAchievement` in `app/lib/typeAchievements.js`, base variant only). The puzzles live here: edit `tutorials/{slug}/puzzles.json` and run `npm run tutorials` to rebuild the data files in `public/tutorials/{slug}/` (the logic-puzzle builds reject any grid without exactly one solution); the gameplay copy beside them is the zip from dm-mpuzzles' `php artisan mpuzzles:tutorial <puzzle id> --data=<that folder>`; tutorial mode itself (`tutorial.js`) is in the dm-mpuzzles gameplay. In local dev, `DM_GAMEPLAY_ORIGIN` proxies `/gameplay/` to another host, so frames stay same-origin as in production. Crossword, Sudoku, Huedoku, Takuzu, Train Tracks, GridFill (Cell Blocks), Head Coach, GuessWord, Word Wheel and Wordsearch have them so far (Huedoku shares Sudoku's builder, `tutorials/sudoku/sudoku.js`, and gameplay).

**Previewing UI for styling:** add `?preview=` with any of `welcome`, `nudge-level`, `level-toast` (home page), `banner-free`, `banner-used`, `gate-used`, `recap-card` (the Wrapped banner), `wrapped` (opens the slides; both use demo data when last month is empty), `wrapped-perfect` (opens the slides with the demo month even when you have real play, so the Perfect month slide shows), `announcement` (the new-puzzle panel, even before its puzzles exist), `challenges` (every challenge card state with demo data, on home and on puzzle covers; its buttons do nothing) (home), `profile-modal`, `profile-toast`, `reset` (account page), `assist-offer`, `assist-modal` (open on a Crossword puzzle page), `cover-last` (the cover's Last time panel with demo stats when there's no previous solve; open a puzzle you haven't started), `friends-members` (adds sample players — two members, a pending request and a declined one — to a group's manage page; their buttons do nothing), `friends-leagues` (replaces the Friends page's leagues with sample ones from `app/lib/friendsPreview.js`, one per league card state: an owner with join requests and more members and puzzles than fit, a new league with just you, a member, a big league, and one awaiting approval; open it signed in so the cards know which are yours; their links lead nowhere), `friends-welcome` (shows the Friends page's no-leagues welcome screen even when you have leagues, signed in or not), `install-prompt` (opens the iOS Add to Home Screen modal on any device), `medal-none`, `medal-bronze`, `medal-silver`, `medal-gold` (/stats: sets this month's puzzles-solved count to 12, 24, 63 or 108 for the month goals card only, and shows the achievements even with no play), comma-separated, or `all`; `?preview=off` clears. It persists for the tab session; `window.__preview('…')` works from the console. Preview buttons never write real settings. `?showOnboarding=1` (or `=N` for slide N) opens the slideshow and `?showTour=1` (or `window.__startTour()`) starts the feature tour on home. `?debug=taste` (or `window.__debugTaste()`; `?debug=off` closes) opens a taste-model panel: per-puzzle score breakdown, confidence, difficulty leans, nudge status, and sample players loaded in memory only (persistence and profile sync are blocked while a sample is active; reload to end). **Phase 5 built** (stats for everyone): `StatsTeaser.vue` replaces locked/empty stats (anonymous visitors on login sites keep stats locked but see the teaser); **challenges are opt-in**: a Challenges panel (`ChallengePanel.vue`) is the third tile of the home summary row (`HomeSummaryRow.vue`: three equal columns from 1200px with Puzzle Streak and Last 7 days; below that those two keep their swipeable row and the panel sits on its own row underneath). Opening the slides records the month in the synced preference `recapWatchedMonth`, so the banner and stats tile say Take a look before and Watch again after. Every slide has a Share button: `renderShareCard` in `app/lib/shareCard.js` draws that slide's stat on a 1080×1350 branded canvas (not on the intro or outro; the slide's colours, white logo, month, puzzle icon from the sprite, "Play at {host}") and hands the PNG to the Web Share API, or downloads it where file sharing isn't supported (`sp_wrapped_share`, `slide`, `method`). The banner and each slide sit on `AmbientField.vue`, a canvas backdrop with one pattern per slide (honeycomb, tiles, rays, clock, pulse, chevrons, speed, constellation, bubbles, letters, confetti; plus `icons`, boxed sprite symbols drifting downwards: one from the `icon` prop (the announcement panel) or a mix from the `icons` array (the Friends welcome uses every puzzle type)) that follows the mouse or device tilt in the slides (the home banners pass `:interactive="false"`; no iOS motion permission is ever requested, so iPhones only get the idle motion), keeps a subtle idle animation, pauses off-screen and is static for reduced motion. The persona stays visible only on each puzzle's stats panel. It's picked by `personaFor` in `app/lib/personas.js` and is about trends rather than streaks: every trait is scored on the last 20 solves, comparing the earlier half with the later half where it's a trend — a new best time, times down 10%+ (On the Up) or up 20%+ (Taking your time), reveals, checks, hints, Head Coach mistakes or GuessWord guesses per game down 40%+ (shown as "down from 4 to 1 a game"), Word Wheel words found up 15+ points; a type only gets the trends its `gameConfig().chart` records. Then when they play: a new routine (play has moved to mornings, afternoons, evenings or late nights), early bird, lunch break, evening, night owl, weekends; then GuessWord's average guesses, 80%+ solves with no help, steady times, welcome back after 14+ days, hint taker and 50+ solves. There are no streak personas (streaks have their own tiles). The strongest wins, and traits within 0.15 of it take turns day by day. The taste model's difficulty lean only looks at the newcomer, purist, improver and hint-taker traits. **Achievements** (on /stats, `Achievements.vue`; catalogue and rules in `app/lib/achievements.js`, fed by `useAchievementStats()` in `app/composables/achievements.js`, which returns null until the archive has loaded) are hidden entirely until the player has solved a puzzle, and show, in order: this month's goals (puzzles solved 20/50/100 as the headline: the month's medal sits centred inside three rounded-square rings, Bronze innermost to Gold outermost, each tracing its progress from the top in its tier colour; the medal is dashed like an unplayed puzzle icon until Bronze, then a metallic tile in the tier's colour (two layered gradients from `--metal-light/base/dark` per tier) with the puzzle icon's shadows, as are the won stamps in Your months; the top of the card, heading included, sits on a flat tint of the current medal's colour (a faint `--primary-rgb` wash before Bronze); Bronze/Silver/Gold chips underneath, then three columns for days played 10/20/every day, every puzzle type and clean solves 5/15/30, each a small progress tile with one ring towards its next level in that level's colour (solid with a tick once the goal is done), all worked out from the lifetime month buckets plus the completion log, so nothing extra is stored), Next up (the first unearned tier of each track in `TRACKS`, the 3 closest to done, with "See all badges" top right opening the All badges modal (every badge grouped by track in `TRACKS`, art for earned ones and the progress tile for the rest, plus secrets); no icon until earned, just a dashed rounded square with the progress traced round it like a puzzle icon's and "6/10" inside), Earned (a card per badge, secrets included, with its art and what you did, from the `done*` strings via `doneKeyFor`; the Challenges counter with its count; newest first, 3 shown, with "See all N earned" top right opening the Your badges modal (large art, what you did and the date earned, secrets included; both modals go full screen on phones and use the shared `Modal`'s `scrollBody` option, so only the body scrolls and the title and close button stay put); when each was earned is worked out from the history in `earnedAt`, e.g. the 10th solve for puzzles-10 or the day a run first hit 7 for streak-7, and badges reached within trimmed months have no date and sort last), Your months (a rounded-square stamp for every calendar month from the first month played to now, coloured by the puzzles tier reached, months with no play as faint dashed "No play" stamps; each year's stamps sit in an `--app-bg` panel with a sticky year label, the row scrolls sideways and starts at the newest end, shows once there are two months, and See all opens the Your months modal with the full history grouped by year, newest first). There is no separate Secret card: found secrets sit in Earned (and the Your badges modal) in date order with a dark "Secret" pill, and the "N more to find" teaser only appears in the All badges modal's Secret group. Everything is a rounded square; circles are only for user initials. Lifetime tracks, built to last years: puzzles (1 to 2,500), streak (3 to 365), days played (7 to 1,000), time with us (1 month to 5 years since the first puzzle), clean (10 to 1,000), variety, monthly medals (months with at least Bronze: 3, 12, 24), gold months (1, 6, 12), archive (solved after the puzzle's release day, 10 to 500), personal bests (beat your best time for that variant, 5 to 100), climber (finish a family's hardest level; the every-family tier only exists when there's more than one family) and challenges. Secrets: night owl (before 5am), early bird (5–7am), comeback (30+ days between play days), lifeline (a saved streak day), full house (every puzzle released that day, solved that day), ghost ("Boo!", a puzzle solved on Halloween), spotless (`secret-perfectionist`, 10 clean solves in a row), weekend break (5 puzzles in one weekend), Christmas cracker (a puzzle solved on Christmas Day). The challenges plugin records every earned key in the synced `unlockedAchievements` (`month:YYYY-MM:{goal}-{tier}` for monthly ones): on load it marks what's already earned silently, then toasts anything new, monthly goals only for the current month. Badge images are `public/img/achievements/{id}.webp`; ids without art show a dotted placeholder.

**New-puzzle announcement:** `HomeAnnouncement.vue` sits in the `.home-banners` row with the "New here?" `HomeWelcome.vue` strip and the Wrapped banner (side by side on desktop, stacked on mobile, full width when alone). Announcements are listed in `app/composables/announcement.js` (`{id, slug, variant}`; Takuzu for now); one shows once its variant has a released puzzle in the archive, for 30 days from the first, unless the type is hidden or it was dismissed (synced preference `dismissedAnnouncements`). Play now opens the newest puzzle; Learn how to play opens a modal with `TutorialPractice` and a Play now button. Funnel events `sp_announcement_click` (`action`: play, tutorials, play-after-tutorial) and `sp_announcement_dismiss`. Body copy is `announcement.body.{slug}`.

**Add-ons (Nuxt layers):** seasonal features live in `layers/{name}/` (auto-registered) and stay out of the main code. The only hook is `<ExtraSlot name="…" />` (`app/components/generic/ExtraSlot.vue`), filled by `registerExtra(slot, component, {order})` (`app/composables/extras.js`) from the layer's plugin; the home page has one in `.home-banners`. A layer loads its own strings with `mergeLocaleMessage` rather than i18n config, so `SITE_LOCALES` deploys aren't affected. `layers/advent/` is the December advent challenge (24 doors of small tasks from the completion log, a Firestore count of players still perfect, four award tiers); see its README for the rules, previews (`?advent=12,demo`) and the Firestore rule it needs.

**iOS install prompt:** `ModalInstallPrompt.vue` shows the Add to Home Screen steps (Share, Add to Home Screen, Add) in a tray that slides up from the bottom (`Modal`'s `:tray="true"` option, usable by any modal). `maybeShowInstallPrompt()` in `app/composables/installPrompt.js` opens it after a puzzle is completed, in the notifications prompt's slot (iOS Safari can't send notifications until the site is installed). It only shows on iPhone/iPad browsers not already running as the installed app (in-app browsers like Facebook, Instagram and the Google app are skipped), once per session and then not again for 30 days; "Don't ask again" stops it for good (`installPromptSnoozedUntil` / `installPromptNever` in preferences). Switched off per deploy with the `installPrompt` feature flag (`NUXT_PUBLIC_FEATURES_INSTALL_PROMPT=false`). Android browsers offer to install from the web manifest on their own.
